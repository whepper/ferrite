# Ferrite 0.3.2 — release notes (source-only release, 2026-11-14)

> **Status: source-only release.** The repository ships the complete source
> tree; no prebuilt binaries are distributed and none are advertised below.
> FDK-AAC redistribution conditions and AAC patent review remain matters for
> qualified assessment before any binary distribution (see
> `0.1.0-third-party-audit.md`); nothing here claims legal or patent
> clearance. Human/legal sign-off of the converter third-party inventory
> remains outstanding (see `rust/convert/THIRD-PARTY-NOTICES.md`).

## 1. What this release is

Ferrite 0.3.2 is the fifth source release of the native Rust audio project:
the float-native AAC-LC encoder derived from the Fraunhofer FDK AAC codebase
(`ferrite-aac` / `ferrite_aac`) and its reference consumer, the FLAC-to-M4A
converter `aac-convert`.

This is a packaging, licensing-hygiene, and public-API release. **The
encoder is unchanged since 0.3.1**: VBR-1 through VBR-6 remain selectable,
VBR-6 remains the Ferrite default, and no encoder algorithm, psychoacoustic
decision rule, quantization, rate-control, or bitstream change is part of
this release. What changes is how the two crates are licensed, what their
published packages contain, and what their public surfaces expose — in
preparation for a first crates.io publication. Neither crate is published to
a registry by this release.

## 2. Highlights

### Corrected package-specific licensing

- **`ferrite-aac` remains FDK-AAC.** The encoder crate keeps `license =
  "FDK-AAC"` with `license-file = "LICENSE-FDK-AAC"`; the complete license
  text, the `NOTICE` with the Third-Party Modified Version notice (dated
  2026-10-26), and all per-file attribution headers are unchanged.
- **`aac-convert` is now `MIT OR Apache-2.0`.** The converter was previously
  (and incorrectly) declared `FDK-AAC`. Its source is independently
  developed application code over the public encoder API — no ported tables,
  no FDK-derived logic — so depending on `ferrite-aac` does not place it
  under the FDK-AAC license. The package now ships the complete canonical
  `rust/convert/LICENSE-MIT` and `rust/convert/LICENSE-APACHE` texts, and
  `rust/convert/THIRD-PARTY-NOTICES.md` documents the boundary explicitly:
  the converter's own code is MIT/Apache-2.0 while the linked `ferrite-aac`
  dependency — and therefore any distributed converter binary — remains
  subject to the FDK-AAC conditions for that dependency.
- **Repository metadata.** `aac-convert` now declares the project repository
  URL. No homepage or documentation URLs were invented.

### Reduced published package contents

- **`ferrite-aac`: 448 files / 12.5 MiB → 96 files / 2.6 MiB**
  (603 KiB compressed). An explicit `exclude` policy keeps the production
  library plus the materials needed to build, use, and understand it.
  Excluded from the crate (retained in the repository): the ~11 MiB oracle
  test corpus under `src/aac_enc/testdata/` **except** the 18 `cfg_*.txt`
  operating-point snapshots, which production module
  `src/aac_enc/psy_config.rs` embeds with `include_str!` and which are
  therefore required in the crate; development tools (`tools/`), local
  Cargo/formatting config, `Android.bp`, app-facing and historical docs,
  and the three corpus-bound/audit-only examples (`aac_bench_wav`,
  `m7_audit_spectral`, `m7_audit_sweep`). The runnable minimal example
  `aac_encode_adts.rs`, the two READMEs-linked integration docs
  (`encoder-integration.md`, `vbr-profiles.md`), and the
  `tests/production_api.rs` integration test ship with the crate. Cargo
  still ships the workspace `Cargo.lock` in the crate (manifest excludes
  cannot omit it); prefer `--exclude-lockfile` when publishing this
  library.
- **`aac-convert`: 64 files / 1.22 MiB → 28 files / ~0.69 MiB.** The
  integration suite (`tests/*.rs`, `tests/common/`) is excluded from the
  crate as strictly repository-development testing with no downstream
  value; it continues to run in repository CI. Of the fixture corpus, only
  the six small FLAC files (76 KiB) referenced by the shipped `src` unit
  tests are retained; the generator script and remaining fixtures stay in
  the repository.

### Public API cleanup

- **Removed the meaningless `aac_enc` feature.** It gated no source code
  (`default = ["aac_enc"]` over an empty feature). The crate is the encoder;
  manifests, CI, scripts, aliases, and documentation were updated
  consistently. The `ferrite-aac` dependency in `aac-convert` is now a
  plain `{ version, path }` declaration.
- **Removed `dummy_call()`.** The `#[doc(hidden)]` placeholder dated to the
  FDK import commit and had no legitimate purpose or users.
- **`common` is public but doc-hidden.** The DSP/transport internals are no
  longer presented as supported user API, but the module stays importable
  because the crate's own doctests exercise it through the public path.
  The supported surface remains `aac_enc::{config, channel_map, encoder}`
  for the library and the documented `batch`/`progress` APIs for the
  converter. No public type was hidden that the public API requires.

### Removed unused build infrastructure

- Deleted `rust/build.rs` and the `rustversion` build dependency. The
  emitted `is_stable`/`is_beta`/`is_nightly` cfgs were consumed nowhere in
  the repository, CI, scripts, or documentation. No build scripts or native
  dependencies remain.

### Documentation and metadata corrections

- Converter README links that pointed outside the published package now
  use stable GitHub blob URLs. The encoder integration guide no longer
  documents a feature-based dependency snippet. Version references in live
  documentation now read 0.3.2; historical release notes are frozen.

## 4. Known limitations

- **Packaging/API release only** (new): no audio-quality, performance,
  capability, bitstream-compatibility, or patent-clearance change of any
  kind is part of 0.3.2. Encoder behavior is identical to 0.3.1.
- **Private Tier-B oracle validation remains unavailable** (unchanged, see
  §3).
- **Perceptual and scope limits unchanged from 0.3.1**: no VBR-6
  superiority claim, AAC-LC only, no bit-exactness claim, 44.1/48 kHz
  mono/stereo, 16-bit encoder input, no resampling or downmixing.
- **No standalone `aac-convert` package yet** (unchanged in kind): its
  `^0.3.2` path dependency on the unpublished `ferrite-aac` crate cannot
  resolve against crates.io; the supported distribution model remains the
  workspace source bundle. Neither crate is published to a registry by this
  release.
- **Legal/notice sign-off outstanding** (unchanged): the converter
  third-party inventory still needs human/legal review before binary
  distribution.
- **MSRV 1.99.1** (unchanged): validated by building and testing on
  1.99.1; older toolchains untested. All dependency MSRVs are at or below
  1.99.1.
- **A declared-but-unused `zerocopy` dependency and an unmaintained
  `paste` advisory (RUSTSEC-2024-0436, informational)** are recorded for
  follow-up; no dependency versions changed in this release.

## 5. Build and installation

Source-bundle model (no registry publish in this release). From `rust/`
with toolchain 1.99.1:

```sh
cargo build --locked --release -p aac-convert   # binary: target/release/aac-convert
cargo test --locked -p aac-convert              # app suite incl. M4A/ADTS checks
cargo test --locked -p ferrite-aac --lib        # encoder suite (Tier-B tests BLOCKED here)
```

Dependencies resolve from crates.io against the committed `Cargo.lock`; no
vendoring is needed and no third-party dependency versions changed in this
release (only the internal `ferrite-aac` 0.3.1 → 0.3.2 requirement). No C
toolchain or FFmpeg is required for builds (FFmpeg is verification-only).

## 6. Licensing and distribution status

Ferrite remains a Third-Party Modified Version of the Fraunhofer FDK AAC
Codec Library for Android (modification notice dated 2026-10-26). This
source-only release ships the complete license text (`rust/NOTICE`,
`rust/LICENSE-FDK-AAC`) in the `ferrite-aac` package and retains all
per-file notices. The converter package ships its own complete MIT and
Apache-2.0 texts plus an explicit licensing-boundary statement; depending
on `ferrite-aac` does not place converter source under FDK-AAC, while
distributed converter binaries remain subject to the FDK-AAC conditions for
the linked codec dependency.

No binary is distributed, so binary-redistribution terms are not exercised;
they — like AAC patent authorization, for which FDK grants **no patent
license** — need separate qualified assessment before any binary
distribution. These notes make no legal or patent-safety claim.
