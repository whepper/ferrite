# Ferrite 0.2.0 — release notes (source-only release, 2026-11-12)

> **Status: source-only release.** The repository ships the complete source
> tree; no prebuilt binaries are distributed and none are advertised below.
> FDK-AAC redistribution conditions and AAC patent review remain matters for
> qualified assessment before any binary distribution (see
> `0.1.0-third-party-audit.md`); nothing here claims legal or patent
> clearance.

## 1. What this release is

Ferrite 0.2.0 is the second source release of the native Rust audio project:
the float-native AAC-LC encoder derived from the Fraunhofer FDK AAC codebase
(`ferrite-aac` / `ferrite_aac`, fixed VBR-5 profile) and its reference
consumer, the FLAC-to-M4A converter `aac-convert`.

The encoded AAC payload is unchanged from 0.1.0: no psychoacoustic decision
rule, quantization, rate-control, TNS, MDCT or bitstream behaviour was
modified. The changes in this release are converter features and UX, encoder
identification metadata, documentation, and one internal encoder correctness
consolidation that was verified not to alter output.

## 2. Highlights

### Encoder (`ferrite-aac`)

- **Short-block M/S grouped Ld correction.** Short-block stereo M/S
  processing now consumes the canonical grouped mid/side energies and their
  freshly calculated log-energies directly from the psychoacoustic model's
  `GroupedOutput` (`grp_data.cpp:211-224`, `psy_main.cpp:1078-1084`). The
  production driver no longer independently regroups M/S energies or
  recalculates grouped Ld, and a write-only history copy was removed. The
  previous regroup implementation is retained only as a `#[cfg(test)]`
  equivalence oracle. Exact-equivalence tests cover multiple short-block
  grouping patterns; re-encoded ADTS output remains bit-identical to the
  committed baselines.

### `aac-convert`

- **Batch usability and metadata handling.** Clearer batch reporting and
  preparation/encoding stage handling; repeated text tags are now preserved
  in source order (joined with `; `) instead of being reduced to the first
  value; optional external cover-art extraction (`--cover-art external` or
  `both`) alongside the default embedded artwork; broader metadata and
  cover-art coverage with additional fixtures and tests.
- **Parallel batch conversion.** Independent files are processed with a
  bounded worker pool: `--jobs N` limits concurrency, `--jobs 1` keeps
  strictly sequential processing, and the default is the number of available
  logical CPUs. Deterministic planning, per-file failure isolation, artwork
  conflict handling and atomic no-overwrite publication are unchanged.
- **Encoder identification and version reporting.** Every M4A output carries
  a `©too` (Tool) atom with the value `Ferrite <version>`, written even with
  `--no-tags`; `aac-convert --version` / `-V` reports the application
  version.

### Documentation

- New end-user manual (`rust/docs/user-manual.md`) covering build,
  conversion, batch behaviour, metadata, progress/exit codes, troubleshooting
  and scope, linked from the project and converter READMEs.

## 3. Compatibility and migration

Existing conversion commands continue to work without changes. The points
below describe observable output differences that may matter for scripts and
tooling.

- **CLI surface.** The flat command-line interface, option syntax, exit-code
  contract and machine-readable per-file result lines are unchanged. `--jobs`
  and `--cover-art` are additive; the default cover-art mode remains
  `embedded`, matching 0.1.0 behaviour.

- **Version output moves to stderr.** `-V` / `--version` now writes to
  standard error (0.1.0 wrote it to standard output), keeping standard output
  reserved for conversion results and summaries. Scripts that captured
  `aac-convert --version` from stdout need to read stderr instead.

- **Repeated metadata values are preserved.** If a source repeats a mapped
  key, distinct non-empty values are kept in source order and joined with
  `; ` in a single atom; exact duplicates and empty values are dropped.
  0.1.0 kept only the first value and emitted a per-file reduction warning,
  which no longer applies. `DATE`/`YEAR` selection and all other metadata
  rules are unchanged (see the user manual).

- **Batch concurrency is now the default.** Batch runs use up to the number
  of logical CPUs instead of one file at a time. Observable differences:
  peak memory can grow with the worker count, and stderr progress lines
  arrive in completion order rather than plan order. Standard-output result
  lines and the final `summary:` line still follow deterministic plan order.
  Pass `--jobs 1` to restore strictly sequential execution and plan-order
  progress.

- **M4A files gain an identification atom.** `©too` = `Ferrite 0.2.0` is
  always written, which costs 37 bytes per M4A file (8-byte atom header,
  8-byte `data` header, 8-byte type/locale, 13-byte value). Audio payloads,
  gapless signalling and source-tag mapping are otherwise unchanged; ADTS
  output carries no metadata container and is unaffected.
- **Encoder API.** The `ferrite-aac` public API is unchanged. The crate is
  still consumed as a source dependency; this repository does not publish a
  registry contract, and this release makes no new API-stability or
  performance guarantee.
- **Versioning.** `0.2.0` is a SemVer minor release: additive converter
  features and metadata, no breaking CLI or API changes.

- The 11 failures in the full lib run are the known Tier-B tests that require
  external C-oracle dumps or C-encoded ADTS references. Those artifacts are

  pre-release baseline for the same missing-artifact reason. They are **not**

  include both in the source package. It must be re-run on a clean checkout
  after the release commit, before packaging or publishing.
- No external quality, listening or FDK-equivalence validation was performed
  for this release; none is claimed.

## 5. Known limitations

Unchanged from 0.1.0 (see `0.1.0.md` §9): fixed VBR-5 only; FLAC input only;
44.1/48 kHz, mono/stereo; 16-bit encoder input with 24-bit truncation and no
dithering; core-tag/single-image metadata model; album loudness defined by
source parent directory; no resampling or downmixing; hard-link-capable
output filesystem required; macOS ARM64 is the verified platform. No
perceptual-transparency or bit-exact FDK-equivalence claim is made.

## 6. Build and installation

Source-bundle model (no registry publish while `ferrite-aac` is an
unpublished path dependency). From `rust/` with toolchain 1.99.1:

```sh
cargo build --locked --release -p aac-convert   # binary: target/release/aac-convert
cargo test --locked -p aac-convert              # app suite incl. M4A/ADTS checks
```

Dependencies resolve from crates.io against the committed `Cargo.lock`; no
vendoring is needed and no dependency versions changed in this release. No C
toolchain or FFmpeg is required for builds (FFmpeg is verification-only).

Ferrite remains a Third-Party Modified Version of the Fraunhofer FDK AAC
Codec Library for Android (modification notice dated 2026-10-26). This
