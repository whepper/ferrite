# Ferrite 0.3.0 — release notes (source-only release, 2026-11-13)

> **Status: source-only release.** The repository ships the complete source
> tree; no prebuilt binaries are distributed and none are advertised below.
> FDK-AAC redistribution conditions and AAC patent review remain matters for
> qualified assessment before any binary distribution (see
> `0.1.0-third-party-audit.md`); nothing here claims legal or patent
> clearance.

## 1. What this release is

Ferrite 0.3.0 is the third source release of the native Rust audio project:
the float-native AAC-LC encoder derived from the Fraunhofer FDK AAC codebase
(`ferrite-aac` / `ferrite_aac`) and its reference consumer, the FLAC-to-M4A
converter `aac-convert`.

The encoder now exposes six selectable VBR profiles (VBR-1 through VBR-6).
VBR-5 remains the upstream-compatible baseline and encodes the same output as
0.2.0. VBR-6 — identical to VBR-5 except for a 20 000 Hz configured bandwidth
— is the Ferrite default. The default output bytestream therefore changes.
No other encoder algorithm, psychoacoustic decision rule, quantization or
bitstream change is part of this release.

## 2. Highlights

### Multi-profile AAC-LC encoding

- **VBR-1 through VBR-6** are selectable through the public Rust API and the
  converter CLI. VBR-1 through VBR-5 are the upstream FDK AAC v3.0.0 rows;
  VBR-6 is a Ferrite-specific extension.
- **VBR-6 is the default** in every default path: `EncoderConfig::new`,
  `EncoderConfig::stereo_48k_adts`, `StreamEncoder`, the `aac-convert`
  wrappers, `BatchOptions` and the CLI parser.
- **VBR-5 is retained unchanged** as the upstream-compatible baseline; its
  encoded output remains byte-identical to 0.2.0.
- **VBR-6** inherits every VBR-5 value except the configured bandwidth
  (20 000 Hz instead of 19 293 Hz), which changes the active
  scalefactor-band set and the bandwidth-derived rate-control values.
- **Profile-specific psychoacoustic initialisation**: per-profile `minSnr`
  and spreading snapshots (18 embedded operating-point files for
  44.1/48 kHz × mono/stereo), `peOffset`, quality factor, TNS and
  active-band derivation. A regression test pins the resulting values
  against the unmodified FDK v3.0.0 init path for 20 production operating
  points.

| Setting | VBR-1 | VBR-2 | VBR-3 | VBR-4 | VBR-5 | VBR-6 |
|---|---:|---:|---:|---:|---:|---:|
| Origin | FDK | FDK | FDK | FDK | FDK | Ferrite |
| Mono nominal bitrate | 32 kbps | 40 kbps | 56 kbps | 72 kbps | 112 kbps | 112 kbps |
| Stereo nominal bitrate (total) | 40 kbps | 64 kbps | 96 kbps | 128 kbps | 192 kbps | 192 kbps |
| Bandwidth limit | 13 000 Hz | 13 000 Hz | 15 750 Hz | 16 500 Hz | 19 293 Hz | 20 000 Hz |
| VBR quality factor | 0.150 | 0.162 | 0.176 | 0.120 | 0.070 | 0.070 |

Nominal bitrates are profile targets, not constant-output guarantees; actual
rates depend on content. The configured bandwidth makes high-frequency bands
available; it is not a guaranteed spectral cutoff. The authoritative
reference, including provenance and per-parameter notes, is
[`../vbr-profiles.md`](../vbr-profiles.md).

### Encoder and conversion

- **Native Rust AAC-LC encoder** — no C toolchain, FFmpeg or external codec
  library is required to build or run.
- **Public profile-selection API** — `VbrMode`, `VbrProfile`,
  `EncoderConfig::new_with_mode`, `with_vbr_mode`, and accessors for the
  selected profile, nominal bitrate, channel bitrate, quality factor,
  configured/effective bandwidth and encoder delay.
- **`aac-convert` supports all six profiles** via `--vbr 1` … `--vbr 6`
  (also `--vbr=N` and case-insensitive aliases). Invalid values exit with
  status 2 and a diagnostic listing the accepted values.
- **ADTS and M4A output**, mono and stereo, at 44.1 kHz and 48 kHz within
  the documented production matrix.
- Conversion diagnostics name the selected profile and the effective
  parameters, for example:
  `14 AAC frames, 1961 bytes, M4A, VBR-6, nominal 192000 bit/s, 20000 Hz bandwidth`.

## 3. Compatibility and migration

Existing conversion commands continue to work, but the default profile
changes. Points that may matter for scripts and tooling:

- **Default output changes from VBR-5 to VBR-6.** On the committed stereo
  fixture the default M4A payload moves from 1 959 to 1 961 bytes and the
  configured bandwidth from 19 293 Hz to 20 000 Hz at the same 192 kbit/s
  nominal stereo rate. Scripts that pin exact output bytes should select
  `--vbr 5` (CLI) or `VbrMode::Vbr5` (API) explicitly.
- **VBR-5 remains byte-identical to 0.2.0.** The committed VBR-5 production
  baselines and their hashes are unchanged.
- **CLI surface is additive.** `--vbr` is new; the flat command-line
  interface, option syntax, exit-code contract and per-file result lines are
  otherwise unchanged. Version output remains on standard error.
- **Rust API is additive.** Existing constructors and methods are unchanged;
  profile selection is opt-in. The default constructor now selects VBR-6.
  `VbrMode` and the profile definition are re-exported from the encoder
  configuration module.
- **M4A identification atom moves to `Ferrite 0.3.0`.** `©too` is derived
  from package metadata and is written even with `--no-tags`.
- **Versioning.** `0.3.0` is a SemVer minor release: new functionality and a
  changed default within the pre-1.0 line, with no breaking CLI or API
  changes. This repository does not publish a registry contract and makes no
  new API-stability or performance guarantee.

- **Bitrate distribution and frame-size testing** across 216 streams and
  111 048 encoded frames, including all six profiles at 44.1/48 kHz,
  mono/stereo, plus the committed WAV fixtures. No frame approached the
  ADTS 13-bit length limit or the per-frame bit cap.

  spectral edge matched its configured bandwidth; 19.5/19.8 kHz tones
  survive under VBR-6 and are removed under VBR-5.

  the M5/M6 migration equality tests, and a new VBR-6 default-profile
  baseline.

### Tests not executed here (BLOCKED)

Ten tests require the private FDK-AAC reference checkout, which is not
available in this environment: nine `phase1*` C-oracle parity tests and
`m55_streams_match_c_reference` (full-stream C comparison). They fail with an
explicit `reference validation artifact missing` message naming the missing
environment variable and the required artifact. **This release does not
claim that those tests passed.** No substitute reference implementation was
used. They remain mandatory in an environment that holds the private
reference checkout.

## 5. Known limitations

- **Private Tier-B oracle validation remains unavailable.** The nine
  phase-1 C-oracle parity tests and the M5.2 full-stream C comparison were
  not executed here (see §4). Compensating evidence: 20-point C init parity,
  committed byte/hash baselines, and the FDK decoder round-trip.
- **No perceptual superiority claim is made for VBR-6.** The 20 kHz
  bandwidth is validated as configuration and as decoded spectral behaviour
  only. No listening test, ABX test or perceptual metric is part of this
  release, and none may be inferred.
- **HE-AAC v1/v2, Spectral Band Replication (SBR) and Parametric Stereo (PS)
  are not implemented.** The encoder produces AAC-LC only; there is no CBR
  mode, no SBR/PS signalling, and no HE-AAC output.
- **Ferrite is not bit-exact with FDK AAC.** The Rust port matches the
  reference at the validated initialisation points and reproduces the
  committed baselines, but no general bit-exactness claim is made.
- **Production matrix.** 44.1/48 kHz, mono/stereo, 16-bit encoder input
  (24-bit FLAC is truncated without dithering), ADTS or M4A output, no
  resampling or downmixing. Other sample rates and channel counts are
  reachable only through the configuration plane and are rejected by the
  production encoder.
- **VBR-3 transient observation.** On one synthetic click-train stimulus,
  VBR-3 encodes below VBR-2. The behaviour is recorded, unexplained at the
  perceptual level, and deferred to a future quality evaluation.
- **`esds` bitrate fields are 0/0.** The muxer declares `maxBitrate` and
  `avgBitrate` as unknown rather than presenting the nominal rate as
  measured. Players ignore these fields.
- **No standalone `aac-convert` package.** Its path dependency on the
  unpublished `ferrite-aac` crate cannot resolve against crates.io; the
  supported distribution model is a workspace source bundle. Neither crate
  is published to a registry by this release.

## 6. Build and installation

Source-bundle model (no registry publish while `ferrite-aac` is an
unpublished path dependency). From `rust/` with toolchain 1.99.1:

```sh
cargo build --locked --release -p aac-convert   # binary: target/release/aac-convert
cargo test --locked -p aac-convert              # app suite incl. M4A/ADTS checks
cargo test --locked --features aac_enc --lib    # encoder suite (Tier-B tests BLOCKED here)
```

Dependencies resolve from crates.io against the committed `Cargo.lock`; no
vendoring is needed and no dependency versions changed in this release. No C
toolchain or FFmpeg is required for builds (FFmpeg is verification-only).

## 7. Licensing and distribution status

Ferrite remains a Third-Party Modified Version of the Fraunhofer FDK AAC
Codec Library for Android (modification notice dated 2026-10-26). This
source-only release ships the complete license text (`rust/NOTICE`,
`rust/LICENSE-FDK-AAC`) in the `ferrite-aac` package and retains all per-file
notices and the third-party inventory (`0.1.0-third-party-audit.md`), which is
unchanged for 0.3.0 because no dependencies were added, removed or upgraded.
New Ferrite-authored files follow the repository's new-file notice policy;
upstream-derived files retain their complete headers.

No binary is distributed, so binary-redistribution terms are not exercised;
they — like AAC patent authorization, for which FDK grants **no patent
license** — need separate qualified assessment before any binary
distribution. These notes make no legal or patent-safety claim.
