## 4. Findings

1. **Project licenses:** `FDK-AAC` (SPDX) for both first-party crates; complete text ships for `ferrite-aac`, not for a standalone `aac-convert` package — hence the workspace-bundle model (§5).
2. **Third-party licenses to accompany distribution:** MPL-2.0 (Symphonia set), Apache-2.0 (`shiguredo_mp4`), MIT (`ebur128`), plus MIT/Apache-2.0-family (or Zlib/BSD-2-Clause alternatives) attributions for the transitive set in §2.
3. **Attribution/notice requirements:** yes — MPL-2.0 notices and source availability for the Symphonia files; Apache-2.0/MIT/BSD/Zlib texts and attributions for the rest; FDK-AAC text retention, modification notices, and no-fee/no-endorsement conditions.
4. **Unusual redistribution requirements:** MPL-2.0 static linking (source-availability obligation for the covered files) and the FDK-AAC binary-redistribution conditions are the two non-trivial items; both need reviewer confirmation, not just script output.
5. **Missing license metadata:** none — every crate in the closure declares a `license` field; no `license = "unknown"` or absent fields.
6. **Incompatibilities:** none detected at the metadata level; compatibility of MPL-2.0-linked code inside an FDK-AAC-licensed binary is a review question for §7, not an automated verdict.
7. **Binary must additionally include:** the FDK-AAC complete text and modification notices, the MPL-2.0/Apache-2.0/MIT/BSD/Zlib texts or an accurate pointer set, and the workspace source bundle (or equivalent complete corresponding source) per §5.

Notes: the root `MODULE_LICENSE_FRAUNHOFER` file is a 0-byte legacy
placeholder from the upstream import, carrying no terms; it is not part of
the distribution model. No global tooling was installed; no versions or
lockfile entries were changed.

## 5. Distribution model (proposed, pending approval)

No registry publish. Distribution is the workspace source bundle built
with the pinned toolchain (`cargo build --locked --release -p
aac-convert`), comprising the corresponding `ferrite-aac` + `aac-convert`
sources, `rust/Cargo.lock`, `rust/NOTICE`, `rust/LICENSE-FDK-AAC`, and
the applicable third-party notices. `cargo package --locked -p
ferrite-aac --list` exits 0 and includes the license texts. Standalone
`cargo package`/`cargo publish` for `aac-convert` remains unsupported
(its archive would not self-contain the FDK-AAC texts).

## 6. AAC patent and distribution considerations (issue checklist, not legal advice)

No definitive claim is made here. Ferrite is not claimed patent-free;
FDK-AAC licensing does not automatically cover Ferrite; a Rust
implementation does not change patent obligations. Each item needs
qualified review before any public or commercial distribution:

- [ ] AAC-LC essential-patent coverage for encoder + distributed binaries.
- [ ] Patent-pool (e.g. Via Licensing) arrangements: required or not, by use.
- [ ] Source-code distribution vs compiled-binary distribution obligations.
- [ ] Personal/internal use vs public/commercial distribution boundaries.
- [ ] Geographic scope of any authorization obtained or required.
- [ ] Whether existing arrangements already cover this use, confirmed in writing.
- [ ] Consumer-facing patent notice wording, if distribution proceeds.
