# Ferrite 0.3.3 — release notes (source-only release, 2026-11-14)

> **Status: source-only release.** The repository ships the complete source
> tree; no prebuilt binaries are distributed and none are advertised below.
> FDK-AAC redistribution conditions and AAC patent review remain matters for
> qualified assessment before any binary distribution (see
> `0.1.0-third-party-audit.md`); nothing here claims legal or patent
> clearance. Human/legal sign-off of the converter third-party inventory
> remains outstanding (see `rust/convert/THIRD-PARTY-NOTICES.md`).

## 1. What this release is

Ferrite 0.3.3 is a converter-only release: `aac-convert` moves from 0.3.2 to
0.3.3 while `ferrite-aac` remains at 0.3.2 (already published to crates.io).
**The encoder is unchanged**: VBR-1 through VBR-6 remain selectable, VBR-6
remains the Ferrite default, and no encoder algorithm, psychoacoustic
decision rule, quantization, rate-control, or bitstream change is part of
this release.

The single user-facing change is fast-start (optimized) M4A output: every
M4A file is now written with the `moov` container metadata placed before the
`mdat` audio data, so players can access track metadata without downloading
the entire file first. Previously all M4A files were written `moov`-last
(`afinfo: not optimized`).

## 2. Highlights

### Fast-start M4A output by default

- All M4A files produced by single-file and batch conversion now use the
  `ftyp` / `moov` / `mdat` layout with no placeholder `free` box. No CLI
  option is required and none was added.
- The relocation is verified in-process: chunk offsets (`stco`, with
  promotion to `co64` when an offset would exceed `u32::MAX`) are patched
  for every track, and the rewritten file is re-parsed to confirm exact box
  coverage with `moov` before `mdat`.
- Seven new integration tests (`tests/faststart.rs`) assert actual box
  order — not configuration — for plain, tagged, embedded-artwork, large
  (1 MiB) sibling-artwork, and experimental edit-list outputs, plus
  byte-identical `mdat` payloads against the ADTS path.

### Metadata and artwork preserved

- Gapless signalling (`iTunSMPB`), the `©too` encoder identification, text
  tags, loudness atoms, embedded and external cover art (JPEG/PNG, 16 MiB
  cap), and the experimental edit-list path are unchanged in content;
  relocation moves only box order and chunk offsets. File sizes shrink by
  the dropped 72-byte placeholder (e.g. the 14-frame stereo fixture reports
  1889 bytes instead of 1961).

### No encoder or audio change

- AAC access units are byte-identical before and after relocation
  (asserted against the ADTS reference in `tests/faststart.rs`), and all
  pre-existing container, metadata, artwork, batch, and ADTS tests pass
  unmodified except two byte-count expectations updated for the dropped
  `free` box.

## 4. Known limitations

- **Fast-start is a layout change, not a compatibility promise** (new):
  `moov`-first improves progressive download and streaming behavior, but no
  universal player-compatibility claim is made beyond the verified
  container validity, offset correctness, and payload preservation above.
- **ADTS output is unchanged and has no fast-start concept** (unchanged in
  kind): ADTS remains the raw-stream engineering/test format.
- **No standalone-`aac-convert` sequencing problem anymore** (changed):
  unlike 0.3.2, the `ferrite-aac 0.3.2` dependency is now published to
  crates.io, so the packaged `0.3.2` version requirement resolves.
  This release publishes aac-convert 0.3.3. The independently licensed
  ferrite-aac crate remains at its existing 0.3.2 publication.
- **Legal/notice sign-off outstanding** (unchanged from 0.3.2): the
  converter third-party inventory still needs human/legal review before
  binary distribution.
- **Encoder scope limits unchanged from 0.3.2**: AAC-LC only, 44.1/48 kHz
  mono/stereo, 16-bit encoder input, no resampling or downmixing, no
  universal gapless-playback claim.
- **MSRV 1.99.1** (unchanged).

## 5. Build and installation

Source-bundle model (no registry publish in this release). From `rust/`
with toolchain 1.99.1:

```sh
cargo build --locked --release -p aac-convert   # binary: target/release/aac-convert
cargo test --locked -p aac-convert              # app suite incl. M4A/ADTS checks
```

Dependencies resolve from crates.io against the committed `rust/Cargo.lock`;
no vendoring is needed. No C toolchain or FFmpeg is required for builds
(FFmpeg is verification-only). The packaged crate additionally carries the
workspace `Cargo.lock` (manifest excludes cannot omit it).

## 6. Licensing and distribution status

Unchanged from 0.3.2: `aac-convert` remains `MIT OR Apache-2.0` with complete
license texts and an explicit licensing-boundary statement; depending on
`ferrite-aac` does not place converter source under FDK-AAC, while
distributed converter binaries remain subject to the FDK-AAC conditions for
the linked codec dependency (complete text in the `ferrite-aac` 0.3.2
package). No binary is distributed. These notes make no legal or
patent-safety claim.
