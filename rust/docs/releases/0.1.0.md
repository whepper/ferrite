# Ferrite 0.1.0 — release notes (source-only release, 2026-11-11)

> **Status: released as source only.** This tag ships the source tree;
> no prebuilt binaries are distributed and none are advertised below.
> FDK-AAC redistribution conditions and AAC patent review remain matters
> for qualified assessment before any binary distribution (see
> `0.1.0-third-party-audit.md` and the M3 checklist in
> `../aac-convert-roadmap.md`); nothing here claims legal or patent
> clearance.

## 1. What Ferrite is

Ferrite is a standalone native Rust audio project: a **float-native AAC-LC
encoder derived from the Fraunhofer FDK AAC codebase** (`ferrite-aac` /
`ferrite_aac`, fixed VBR-5 profile), with no FFI surface and no decoder
crate. It is not affiliated with or endorsed by Fraunhofer. There is no
1:1 or bit-exact equivalence claim with FDK AAC.

## 2. What aac-convert does

`aac-convert` is the reference production consumer: a focused
FLAC-to-M4A conversion tool for personal music libraries. One FLAC file
converts to one output; one directory converts to a mirrored output tree.
It owns FLAC decoding, metadata, cover art, loudness analysis, M4A muxing,
and atomic publication around the fixed encoder.

## 3. Main capabilities

- Single-file and recursive batch conversion with deterministic,
  byte-sorted planning and per-file failure isolation.
- Safe reruns: existing outputs are never overwritten (`--skip-existing`
  resumes a partial batch); duplicate destinations abort before anything
  converts; dry-run previews without writing.
- Integrity-checked decoding (FLAC MD5 when present), validated ADTS
  frames, and atomic hard-link publication with temp-file cleanup.
- Core metadata, single-image cover art, and ReplayGain 2.0 + `iTunNORM`
  loudness on M4A; `iTunSMPB` gapless signalling.

## 4. Supported formats and configurations

| Item | Supported |
|---|---|
| Input container | Native FLAC (`.flac`, case-insensitive) |
| Sample rates | 44 100 Hz, 48 000 Hz |
| Channels | mono, stereo |
| Bit depth | 16-bit; 24-bit truncated to 16-bit with a per-file warning |
| Encoder | AAC-LC, fixed VBR-5, 1024-sample frames, 1600-sample delay |
| Output | Audio-only M4A (default for batch) or ADTS (engineering/test) |

Everything else — other rates, channel counts, bit depths, containers,
resampling, downmixing, quality settings — is rejected or absent by
design, never silently approximated.

## 5. CLI usage examples

```sh
aac-convert album/track01.flac converted/track01.m4a
aac-convert ~/Music/rips/ ~/Music/m4a/ --skip-existing
aac-convert --format adts ./music/ ./converted-adts/
aac-convert --dry-run album/ ./converted/
aac-convert --verbose album/ ./converted/
```

Exit codes: `0` success (including clean dry-runs and all-skipped
reruns), `1` per-file failures, `2` usage errors, `3` fatal setup
errors. Warnings go to stderr as `warning: <input>: …`; failures as
`error: <input>: …`; batches end with a `summary:` line.

## 6. Metadata and artwork behavior

M4A carries the ten core Vorbis-comment text tags (title, artist, album,
track/disc numbers with totals, album artist, date/year, genre, composer,
comment) as single-valued UTF-8 atoms — first non-empty value wins, with a
per-file warning when distinct values are reduced. Unmapped keys (ISRC,
MusicBrainz IDs, label, etc.) are counted for `--verbose` and never
guessed into atoms. At most one JPEG/PNG cover image (≤ 16 MiB, magic-byte
detected, deterministic front-cover-first selection). `--no-tags` strips
user atoms but keeps gapless signalling. Tags never alter audio payloads
(decoded output is identical with and without tags, verified in M2).

## 7. Gapless playback behavior (qualified)

M4A carries Apple `iTunSMPB` (1600-sample priming, source count, tail
padding) with Apple-style `M4A` brands and no edit list. Decoders that
honor it present exactly the source sample count — verified with FFmpeg
(sample-exact decode) and macOS CoreAudio (`afinfo` reports the exact
trim) on the committed fixtures. Container duration fields keep the
encoded-stream timeline, so duration displays may exceed the trimmed
audio. VLC and GUI players are unverified or approximate. No universal
gapless-playback claim is made.

## 8. Performance characteristics

Evidence, not guarantees: the encoder baseline reports roughly 229×
realtime on its corpus (see `docs/aac-enc-performance-baseline.md`), and
the integration guide records a 5-minute stereo 48 kHz encode in about
0.7 s in release mode on the author's machine. Batch overhead is one
sorted path list; conversion is sequential with bounded memory (8 000-frame
pushes, streaming muxer). Actual speed depends on hardware, input, and
build profile; the 0.1.0 contract promises correctness and safety
invariants, not throughput.

## 9. Known limitations

Fixed VBR-5 only; no resampling/downmixing; 24-bit input truncated
without dithering; core-tags/single-image metadata model; albums are
source-parent directories (mixed rate/channel layouts receive
track-level loudness only, album atoms omitted with a warning); silence
omits loudness atoms; sequential conversion; hard-link-capable
filesystem required (FAT/exFAT fail safely per file); orphan temp files
possible only after abrupt termination (manual cleanup); macOS ARM64
verified, other platforms as listed in the M3 platform matrix
(`../aac-convert-roadmap.md` §11.3). No perceptual
transparency or FDK-equivalence claim.

## 10. Build and installation instructions

Source-bundle model (no registry publish while `ferrite-aac` is an
unpublished path dependency). From `rust/` with toolchain 1.99.1:

```sh
cargo build --locked --release -p aac-convert   # binary: target/release/aac-convert
cargo test --locked -p aac-convert              # app suite incl. M4A/ADTS checks
```

Requires Rust 1.99.1 (`rustup install 1.99.1`); dependencies resolve from
crates.io against the committed `Cargo.lock`. No vendoring needed. No C
toolchain or FFmpeg for builds (FFmpeg is verification-only).
