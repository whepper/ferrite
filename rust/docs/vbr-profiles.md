# Ferrite VBR Profiles (VBR-1 through VBR-6)

**Audience:** application developers and `aac-convert` users selecting an
encoding profile. For the public Rust API see
[`encoder-integration.md`](encoder-integration.md); for the converter CLI see
[`../convert/README.md`](../convert/README.md) and the
[Ferrite User Manual](user-manual.md).

Ferrite implements six selectable AAC-LC VBR profiles. VBR-1 through VBR-5
are the upstream Fraunhofer FDK AAC v3.0.0 rows
(`aacenc.cpp:199-205` bitrates, `bandwidth.cpp:152-162` bandwidths,
`qc_main.cpp:122-133` quality factors). VBR-6 is a Ferrite extension: it
inherits every VBR-5 setting except the configured bandwidth (20 000 Hz
instead of 19 293 Hz). VBR-6 is the default when no profile is explicitly
selected; VBR-5 remains available unchanged as the upstream-compatible
baseline. Do not present VBR-6 as an upstream FDK profile, and do not claim a
measured quality improvement from 20 kHz without supporting measurement.

## Authoritative profile reference table

Stereo nominal bitrate is the total for two channels. The original FDK table
(`aacenc.cpp:199-205`) specifies the stereo value per channel; the effective
stereo total is twice that value. Mono values are totals (one channel).

Bandwidth is a maximum coding bandwidth, subject to the sample-rate Nyquist
limit (`min(bandwidth, sample_rate/2)`). At 44.1/48 kHz the clamp is inactive
for all six profiles; below ~38.6 kHz it binds (e.g. 8 kHz → 4 kHz cap).

## What the settings do

### Nominal bitrate

Mono and stereo nominal rates are profile targets used to initialise
rate-control state (`FDKaacEnc_GetVBRBitrate`, `calc_bits_per_frame`,
`derive_qc_init` → `averageBits`, `meanPe`, element grants). They are not
constant-output (CBR) targets: VBR derives thresholds from the signal and the
quality factor and uses the bit cap only as a safety limit
(`qc_main.cpp:798-800`, `adj_thr.cpp:2810,2869-2884`). The same profile
produces very different average rates on different content (e.g. ~18 kbit/s
on sparse synthetic fixtures vs ~188 kbit/s on orchestral material at VBR-5).
See `docs/aac-enc-vbr5-profile.md` §6 for the mechanism and measurements.

For mono the total equals the per-channel entry; for stereo the total is
twice the per-channel entry (e.g. VBR-5 stereo 2 × 96 000 = 192 000).
Multichannel configurations use the stereo per-channel entry times the
effective (non-LFE) channel count, matching `FDKaacEnc_GetVBRBitrate`.

### Bandwidth limit

The encoder's maximum coding bandwidth constrains the low-pass line
(`floor(2 × bandwidth × frameLength / sampleRate)`) and therefore the active
scalefactor-band count. Fewer active bands means bits are distributed over a
narrower spectrum; a wider bandwidth leaves more high-frequency bands
available for coding when the signal warrants it.

The sample-rate Nyquist limit applies first: effective bandwidth is
`min(configured, sample_rate/2)`. At 44.1/48 kHz all six configured values
pass through unchanged.

Upstream VBR-5 is 19 293 Hz; Ferrite VBR-6 is 20 000 Hz and inherits
everything else from VBR-5. Configuring a bandwidth does not prove the
bitstream contains energy up to that frequency; it only makes those bands
available. Distinguish configuration validation (low-pass line, active-band
count, `meanPe`) from spectral-output validation.

### VBR quality factor

An internal psychoacoustic threshold-adjustment parameter
(`tableVbrQualFactor` → `QC_STATE.vbrQualFactor` → `AdjThrInit` →
`atsElem->vbrQualFactor`), not a direct quality score, bitrate multiplier, or
user-facing quality percentage. At a high level it scales the per-band
threshold lift (`redVal = vbrQualFactor × chaosMeasure × frameEnergy^(1/4)`,
`reduceThresholdsVBR`): a smaller factor lifts thresholds less and therefore
spends more bits to meet them. The values are empirically tuned per profile
and are not a linear scale — the table is non-monotonic (VBR-3 0.176 is the
coarsest, VBR-5/VBR-6 0.070 the finest in this mechanism). This is a statement
about the formula, not a listening result.

### Afterburner

FDK's analysis-by-synthesis scalefactor refinement (`invQuant = 2`):
after the initial scalefactor estimate, the encoder requantizes,
inverse-quantizes, measures distortion, and assimilates single/multiple
scalefactors (`sf_estim.cpp:1046-1292`, gated by `invQuant > 1`). It does not
change the quality factor, thresholds, bandwidth, or frame cap; it changes how
well the chosen scalefactors fit the thresholds, which can change both
distortion and bit consumption. Ferrite deliberately enables it for all VBR
profiles; upstream FDK defaults it off. The stripped reference tree forces it
on, and Ferrite matches that forced-on reference.

### TNS (Temporal Noise Shaping)

An LPC filter applied in the frequency domain to shape quantization noise
over time (`aacenc_tns.cpp`). LC configuration is max order 12 (long) / 5
(short), coefficient resolution 4/3 for bitrates ≥ 16 kbit/s per channel
(all six profiles satisfy this), with stop band
`min(tnsMaxBands, sfbActive)` so bandwidth indirectly moves the TNS stop
line. TNS remains enabled for all VBR profiles; it is signal-controlled per
frame.

### PNS (Perceptual Noise Substitution)

Noise-like bands signalled by energy instead of spectrum. Upstream AAC-LC
initially enables PNS, but FDK's post-configuration logic disables it when a
VBR mode is selected (and when TNS is disabled)
(`aacenc_lib.cpp:1173-1176`). Ferrite implements the effective behaviour:
PNS is off for every VBR profile (`NO_NOISE_PNS`, zero noise energies). Do
not mistake the initial default for the effective VBR configuration.

## Profile selection examples

### Default encoding (VBR-6)

```rust
use ferrite_aac::aac_enc::config::{EncoderConfig, TransportType};
use ferrite_aac::aac_enc::encoder::Encoder;

let cfg = EncoderConfig::new(48000, 2, 1024, TransportType::Adts)?;
// cfg.vbr_mode() == VBR-6
let mut encoder = Encoder::new(cfg)?;
```

```rust
let cfg = EncoderConfig::stereo_48k_adts(); // VBR-6
```

### Explicit VBR-5 (upstream baseline)

```rust
use ferrite_aac::aac_enc::config::{EncoderConfig, TransportType, VbrMode};

let cfg = EncoderConfig::new_with_mode(48000, 2, 1024, TransportType::Adts, VbrMode::Vbr5)?;
// or: EncoderConfig::new(...).with_vbr_mode(VbrMode::Vbr5)
```

### Explicit VBR-1

```rust
let cfg = EncoderConfig::new_with_mode(48000, 2, 1024, TransportType::Adts, VbrMode::Vbr1)?;
```

### Mono input

```rust
// Mono VBR-6: nominal 112 kbit/s, bandwidth 20 kHz.
let cfg = EncoderConfig::new(48000, 1, 1024, TransportType::Adts)?;
```

```rust
// Mono VBR-1: nominal 32 kbit/s, bandwidth 13 kHz.
let cfg = EncoderConfig::new_with_mode(48000, 1, 1024, TransportType::Adts, VbrMode::Vbr1)?;
```

### Stereo input

```rust
// Stereo VBR-6: nominal 192 kbit/s total (2 × 96 kbit/s).
let cfg = EncoderConfig::new(48000, 2, 1024, TransportType::Adts)?;
```

### `aac-convert`

```sh
# Default (VBR-6):
aac-convert track.flac track.m4a

# Explicit VBR-5 (upstream baseline):
aac-convert --vbr 5 track.flac track.m4a

# Explicit VBR-1:
aac-convert --vbr 1 track.flac track.aac

# Batch with VBR-4:
aac-convert --vbr 4 music/ converted/

# Invalid values fail with exit 2:
aac-convert --vbr 7 track.flac track.m4a
# error: invalid --vbr value: 7 (expected 1, 2, 3, 4, 5, or 6)
```

Single-file output names the selected profile and effective parameters:

```text
converted track.flac -> track.m4a (14 AAC frames, 1961 bytes, M4A, VBR-6, nominal 192000 bit/s, 20000 Hz bandwidth)
```

Batch headers name the profile:

```text
batch: 2 files, format M4A, VBR-6, recursive, 10 jobs
```

## Implementation notes and verification

All profile-specific values below were verified against the UNMODIFIED
FDK-AAC v3.0.0 implementation (`mstorsjo/fdk-aac`, tag `v3.0.0`, commit
`a68a51aa45d86a43c7b228e3d45624af09dcdd8d`) by driving its real init path
(`FDKaacEnc_InitPsyConfiguration` for LONG/SHORT,
`FDKaacEnc_InitTnsConfiguration`, and `FDKaacEnc_QCInit` which calls the
real `InitElementBits` + `AdjThrInit`) for every VBR-1..5 operating point
at 44100/48000 Hz, mono/stereo — see
`tools/enc-oracle/dump_vbr_init_configs.cpp` (build/run instructions in
its header; output is deterministic). The dump pipeline re-emits the four
pre-existing VBR-5 snapshots byte-identically as a self-check before any
new file is trusted, so the new snapshots reproduce the established oracle
workflow rather than a parallel implementation. The per-profile regression
test `vbr_profiles_match_c_reference_init` pins the resulting values
(20 production combos).

### Which psychoacoustic parameters are profile-specific

| Parameter | Profile-specific? | Detail |
|---|---|---|
| `minSnr` snapshots | Yes (per pch) | 18 unique `(rate, pch)` snapshots at 44100/48000 Hz, committed as `cfg_<sr>_<pch>.txt` and resolved by per-channel bitrate. VBR-1 mono and VBR-2 stereo share pch=32000 (byte-identical FDK dumps, verified during generation, not assumed). |
| `peOffset` | Yes (one case) | 50 for VBR-1 stereo (20 kbit/s per channel, the only operating point below 32 kbit/s); 0 otherwise. Exact C formula `max(50, 100 - fMultI(0x666667, chBitrate))`. |
| `vbrQualFactor` | Yes | Per-profile table values (`0.150/0.162/0.176/0.120/0.070`), Q31 `FL2FXCONST_DBL` forms verified against the C table. |
| `meanPe`/`peMin`/`peMax` | Yes (derived) | Via bandwidth and bitrate through the shared `derive_qc_init` path; verified equal to C `QCInit` outputs. |
| `averageBits`/`maxBits`/`minBits`/`bitRes`/`maxBitFac` | Yes (derived) | Via nominal bitrates through the shared path; verified equal to C. |
| SFB low-pass/active bands | Yes (derived) | Via profile bandwidth; verified equal to C `lowpassLine`/`sfbActive`. |
| `allowIS` | Yes (derived) | Via `(bitrate / bandwidth) < 5`; verified equal to C. `allowMS` is always true. |
| Spreading `MASKHIS` LONG | One case | VBR-1 stereo takes the `<= 20000` low-bitrate branch (factor 1.5 instead of 2.0). The resulting table is byte-identical to the threshold `hi` table at every sample rate (verified across all 12 rates), so the existing immutable data is shared rather than duplicated. SHORT windows never branch. |
| TNS bands/lines | Yes (derived) | `stopBand = min(maxBands, sfbActive)` etc. via the shared `TnsConfig::new`; verified equal to C `InitTnsConfiguration` for all profiles. |

### Which parameters are shared across profiles

`chaosMeasureOld` (`0.3`), `ahParam` (`modifyMinSnr=1`, `startSfbL=15`,
`startSfbS=3` — every VBR-1..5 per-channel bitrate is `>= 20000`, so the
disabling branch never fires), `minSnrAdaptParam` (`maxRed`,
`startRatio`, `redRatioFac`, `redOffs`), `bits2PeFactor` (LC default;
`dZoneQuantEnable` is 0 for LC since it additionally requires low-delay),
`peCorrectionFactor`, `dynBitsLast`/`peLast` init, BRES params,
`maxIter2ndGuess`, TNS `maxOrder`/`coefRes`/`threshOn`/`limitOrder`, and the
`invQuant = 2` afterburner path — all byte-identical across the 20
reference dumps.

### VBR-6 definition (unchanged)

VBR-6 reuses the VBR-5 `minSnr` snapshots by Ferrite definition (same
per-channel bitrates: 96/112 kbit/s). Its bandwidth difference is carried
by the SFB/low-pass/active-band path and the bandwidth-derived QC values
(`meanPe` etc.), exactly as before; VBR-6 output is unchanged and remains
pinned by the existing production baselines and `aac-convert` fixtures.
Configuring 20 kHz does not by itself prove output energy at 20 kHz; the
distinction between configuration validation and spectral-output
validation from the previous revision still applies.

### Remaining limitations

- `minSnr`/spreading snapshots cover the production rates (44100/48000 Hz)
  only. The config layer accepts 12 sample rates, but the production
  `Encoder` gates to 44100/48000 Hz, so no other rate can reach the
  snapshot lookup; unknown combinations fail closed with a clear panic
  rather than silently reusing data.
- No listening test, ABX test, or perceptual metric is part of this
  validation. Bit-exact init parity plus the structural/decoder checks do
  not establish transparency or perceptual equivalence.
