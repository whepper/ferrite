## 1. Decision D1 — Authorize M4.0 and M4.1; staged authorization thereafter

**Decision.** M4.0 (governance: this record, the baseline investigation and
checkpoint plan, M4.1 readiness confirmation) and M4.1 (the float threshold
initialization stage of the M4 blueprint, §6 stage M4.1 / task FPE-4.1a) are
**authorized**. Authorization for every later M4 stage (M4.2 seam mirror,
M4.3 clip, M4.4 threshold spreading, M4.5 spread energy, M4.6–M4.10) is
**staged**: each requires an explicit owner authorization issued against
the stage's completed predecessor evidence.

**Rationale.** The M4 blueprint defines small, independently testable
stages; the owner elects to authorize at stage granularity rather than for
the milestone as a whole, so each step's evidence is reviewed before the
next begins.

**Scope.**

- M4.0 is complete with this record and the two documents it references
  (no production change).
- M4.1 comprises **only** the changes specified in the blueprint §6 stage
  M4.1 and Appendix B task skeleton: a new `init_threshold_f` in

  [`../M4-baseline-checkpoint-plan.md`](../M4-baseline-checkpoint-plan.md)

  readiness is not authorization to begin.

**Consequences.** The ADR-0001/ADR-0004 amendments identified in the
blueprint §9.1 remain **proposals** (not made; each requires its own
authorization). M4.2 (the A-13 seam implementation) is not authorized by

## 2. Decision D2 — A-13 resolved: FPE-side composite advance-stage mirror

**Decision.** The A-13 seam question is resolved for the M4–M7 window in
favour of the **FPE-side composite mirror** (blueprint §3.2, Option A).
Recorded explicitly, as required:

1. **Q31 remains unchanged and remains the reference/default engine.** No
   Q31 production file changes in M4; `PsyEngineKind::default()` stays Q31.
2. **FPE gets its own composite advance-stage mirror**
   (`fpe::thresholds::advance_thresholds`, blueprint §3.2), mirroring
   `psy::advance_thresholds` (`psy.rs:1256-1292`) stage-for-stage over
   FPE-owned state and scratch. The mirror is implemented at stage M4.2
   (not yet authorized), with all value stages still delegating to the same
   Q31 kernels and a byte-identity gate.
3. **`tns_encode_channel` remains delegated at this stage** — the accepted
   M3 mirror-then-replace discipline continues unchanged through M4–M6; the
   M7 TNS/LFE integration review revisits it with fresh evidence.
4. **`finish_channel` remains shared** — output assembly (grouping, Ld
   vectors, `nm1` readout) operates on stored ints and stays the reused Q31
   assembler behind `fpe::output::assemble_channel`.
5. **No Q31 kernel extraction or refactoring is authorized.** The
   alternative (minimal additive baseline-gated Q31 kernel extraction) is
   **rejected**: it modifies Q31 production code against the charter's
   non-goals (`00` §4), couples the engines ADR-0001 explicitly rejected,
   and buys no numerical benefit (blueprint §3.2 item 4).
6. The M4 sub-decisions recorded with it (blueprint §3.3): **no float
   threshold lane through the TNS block** (the float lane restarts at the
   advance stage from the exact fraction image of the stored threshold),
   and **spread-energy input is the stored-energy fraction image**. Both
   may be revisited at M7.

**Rationale.** The full rationale, evidence and rejected alternatives are
in blueprint §3. In brief: the charter forbids Q31 refactoring, ADR-0001
already accepts orchestration duplication, the M3 precedent
(mirror-then-replace over `tns_encode_channel`) established the pattern,
and drift risk is bounded by a zero-value-change seam stage gated by
byte-identity.

**Consequences.** A-13 moves from *Open (architecture/planning)* to
*Decided* (see the register update, §6). R-02 (orchestration drift) remains
active with the blueprint's mitigation (seam-first mirror + per-frame
differential). The proposed ADR-0001 amendment (recording the mirror
ownership and the rejected extraction) requires separate authorization.

## 4. Decision D4 — Historical pins immutable; successor baselines require explicit approval

**Decision.**

1. **Historical baseline pins are immutable.** The seven preserved FPE pins
   (six `r21b_p0b_*` plus `probe_envelope::g1_probe_corpus_aggregate`), the
   187 unjudged S4 flips, the frozen E1 schema v2, MDEF v2, the accepted
   Group E bundle (36/36) and AC9SCHEMA 1 (5/5), and every pinned evidence
   aggregate and byte baseline are preserved as-is. **No silent
   rebaselining is permitted.**
2. **Any successor baseline requires explicit owner approval.** M4 stages
   will shift the observed values behind the existing pins (thresholds and
   spread are new divergence carriers). Any successor pin set (e.g. an
   M4 divergence-characterization baseline at stage M4.8), any pin
   retirement, and any update to a pinned aggregate must be proposed to the
   owner with the underlying evidence and **approved before it takes
   effect**. Until then, the M3 pins stand unchanged and their failures
   remain the documented, expected state.

**Rationale.** The pins are evidence provenance for accepted decisions
(A-03/A-21/OD-6); silently rewriting them would destroy the audit trail
exactly when new divergence arrives. The successor mechanism keeps history
immutable while allowing forward motion.

**Consequences.** The M3 pins remain observed failures (expected). Any M4
test that would touch pinned values must route through the successor-approval
mechanism. The blueprint's M4.8 divergence-characterization campaign is the
designated proposal vehicle; it is not yet authorized.
