# R2.2 AC-9 — M3 Scope Matrix (28 November 2026)

**Status:** Implementation and classification record. No owner acceptance is
claimed in §§1–4; §5 records the subsequent owner disposition.
**Baseline:** `189e6a79b78a84dcc5be88eaca5ffaba24097acc`.
**Authority for M3 scope:** `findings-register.md` §13 (M3 boundary set),
`validation-roadmap.md` §5 (acceptance gate map, D-1…D-5), R2.2
downstream-decision-safety design §6 (AC-2/AC-9), and the AC-9 report §3.4.
**Rule applied:** AC-9 §3.4 is an inventory, not a requirement list. A family
is classified M3-mandatory only when a cited M3/R2.2 criterion needs its
decision evidence, or when its absence would make AC-9 evidence untruthful.

## 1. Classification vocabulary

| Class | Meaning |
|---|---|
| **M3-mandatory** | Needed for the M3 boundary: R2.2 AC-2 stage execution/assertion, D-1/D-3/D-4/D-5 decision quantification, AC-9 truthfulness, or AC-10 evidence readiness. |
| **Later-phase** | Not required by the M3 boundary; AC-9 permits an explicit `Required`/`Unobserved`/`NotApplicable` record. Deferred without weakening AC-9. |
| **Unresolved / unobservable** | The production branch did not occur in the authorized corpus; no observation is invented. Recorded honestly and not counted as coverage. |

## 4. M3 conclusion from the matrix

The M3-mandatory remainder was: S1 patch execution/inheritance record; S2
peak/valley and MS cross-tweaks; S4 all-dead/gain inversion; S6 MAX_QUANT,
crash error, exit predicates and named accounting margins. These are now
implemented as test-only evidence. The remaining listed families are either
genuinely unobservable or later-phase under the cited M3 boundary. AC-9 is
ready to enter its single AC-10 independent acceptance review, subject to the
reviewer confirming the classifications above; this document does not declare
owner acceptance or M3 completion.
