## A. Scope and methodology

**Purpose of Group D.** Establish, per downstream stage (S1 PE, S2 VBR
thresholds, S4 scalefactors, S6 bit allocation) plus the unsupported domain
(A6), exactly which Q31-vs-FPE differences exist, on which side of each exact
production decision boundary they fall, and which conclusions are justified.
Group D characterizes; it does not judge safety, perceptual impact, or default
acceptance.

**Evidence methodology.** Four evidence classes are kept strictly separate:

- **Captured:** production state snapshots taken by the test-only capture path
  (`R22Capture` per stage, `FrameSnapshot`, oracle S1/S4/S5/S6 fixtures with
  `s6init` vectors). Captures are read-only inputs to attribution.
- **Replayed:** unchanged production functions called on cloned operands with
  replay-equality asserted — within each arm independently (`replay_frame`;
  `qc_main_frame` from forged pre-frame grant state; `exit_matrix_step`;
  `calc_thresh_exp`; `calc_sfb_quant_energy_and_dist` / `calc_inv_ld_data`;
  crash recount via `static_bits_cpe`). A replay proves capture/replay fidelity,
  never cross-arm identity.
- **Reconstructed:** margins, scaled thresholds, `bits_to_save` terms, saved-bit
  chains and grant-rebalance arithmetic recomputed from recorded operands
  (wrapping arithmetic identical to production). Reconstructions are checked
  against captured outcomes; any mismatch fails loudly.
- **Unobserved:** paths no valid driver setup reached (recorded explicitly, never
  counted as passes). See §§F–G.

**Q31/FPE comparison methodology** (design §10.2). Within-arm replay correctness
is the hard gate (each arm reproduces its own production result bit-for-bit);
cross-arm comparison is differential classification, not an identity requirement.
A difference is classified and attributed; it is never hidden and never
automatically accepted.

**Test-only instrumentation boundaries.** All probes (`scf::step3_probe`,
`rate::s6_probe`) are `#[cfg(test)]`; production builds contain no probe
behaviour. All attribution tests live in the test tree (`is_ms.rs` A6/S1/S2,
`s4_step3.rs`, `rate.rs` S6 tests, `trace.rs` margin/boundary tests). Probe-on/off
and capture-on/off canaries assert byte/digest/gain/scf/quant/state identity
(S4 §E, S6 §F). Production isolation is therefore evidenced, not assumed. No
Group E bundle (`docs/evidence/fpe-r22/`) was created here; no D-6 recurrence
analysis was performed.

  unchanged production functions on cloned operands (or test-only probes that

  probe/capture canaries green. Full library suite this pass: **620 passed,
  18 failed, 2 ignored** — the 18 failures are exactly the 7 pre-existing
  FPE-3.2 pin failures plus the 11 documented Tier-B environmental blockers (§H);
  **no Group D evidence test fails**.
- **Numerical behaviour characterized.** Exact decision boundaries with
  strict/inclusive equality semantics are pinned for every S1/S2/S4/S6/accounting
  edge examined; minimum-absolute-margin distributions and exact-zero cases are
  reported where observed. `thr_exp` cross-arm equality is asserted via
  production recomputation; short-path scaled thresholds are derived and
  output-checked.
- **Actual coding-decision differences observed.** 45 S1 flips, 33 S2 flips and
  187 S4 intermediate flips are retained as observed Q31-vs-FPE branch
  differences with margin attribution. They are characterized, not judged: no
  defect, harmlessness, or perceptual-neutrality claim is made or implied.
- **Synthetic-only branch coverage.** Gain-bump retry, crash recovery with
  `saved_met`, recount/rebalance, exit-matrix transitions, fallback-arm
  predicate, and unit-level error primers are demonstrated on synthetic budgets
  or direct unit calls only. They prove the mechanism, not corpus occurrence.
- **Unobserved behaviour.** Fallback via a valid driver, full-band wipeout,
  exhausted SFB search, driver-level QuantError/BitresTooLow, and any S4
  dist/energy equality case remain unobserved. The `check_min_frame_demand`
  stub (`true`) bounds what the exit-matrix evidence can claim about the
  emergency arm.

  have no R22-captured operands stay `MarginDerivationRequired` in `trace.rs`
  (S4 step-3 edges, S6 crash stop-distance; see §I on the S2 short-path marker).
  Closing them needs an owner-scoped Group A capture extension, not Group D
  re-analysis. The seven FPE-3.2 baseline pin failures and the 11 Tier-B
  environmental blockers are preserved as separate categories (§H).
- **Not claimed.** No perceptual equivalence, no decision safety, no default
  acceptance, no full domain coverage, no M4 readiness. Technical attribution is
  not presented as proof of safety. The nine conditional R2.1-B acceptances
  (incl. F-20/22/26 OD-2 scope) stay conditional; Group C limitations
  (`s6_multipass`/`s6_crash` unobserved in OP-1…6) are unchanged; Tier-B C-parity
