- Investigation confirmed DeepSeek's account against the implementation

  per-window bounds, where TNS-reused windows contribute their
  retained `q31_tol` (e.g. F-19 ch0: `tol=96.130 = 32.116 [w1
  envelope] + 32.002 + 32.012 [w2/w3 TNS-reused]`), while the grouped

  in the group (`Q=0.013100/T=0.000206/R=4.5` for F-19 ch0). The two
  sums therefore do not re-derive each other, and the grouped Q/T/R
  must be read as retention sums, not as a per-window envelope
  reconstruction.
- What is exact and unchanged: the grouped `tol` (the actually
  applied comparison bound), the grouped Δ, the utilisation, the
  `supported` flag, and every per-window envelope row (all
  envelope-backed differing windows pass their own bounds;
  TNS-reused windows are audited under retained `q31_tol`, never
  claimed as envelope comparisons).
- Affected rows: grouped rows for F-19/F-20/F-21/F-22 (groups g1/g2
  contain TNS-reused windows); unaffected: all F-23…F-26 grouped
  rows (g3 is the single envelope window w7, so grouped Q/T/R/tol
  coincide with the window terms).
- Report fix: §8 now carries this distinction explicitly (it
  previously presented grouped Q/T/R/tol without the TNS-reused
  caveat). No calculation or aggregation rule was changed — the
  previous text was imprecise, not the math.

## 3. Grouped / TNS-reused window explanation (consolidated)

For each grouped finding band, the grouped row is the exact applied
comparison (`Δ` vs summed bound, `supported`, pass/fail), while the
envelope-identity terms live per window:

- Groups g1 (`w1..4`) and g2 (`w4..7`) each contain one envelope-backed
  differing window (w1, w4) plus TNS-reused windows. Example (F-19
  ch0, IS band 23): grouped `got=66 want=65 Δ=1 tol=96.130 pass`;
  contributing window w1 `got=59 want=58 Δ=1 Q_b=0.004368
  T_b=0.000092 s_b=18 tol=32.116000 util=0.031137 pass`; w2/w3 are
  TNS-reused (`Q_b=T_b=0`, `q31_tol` 32.002/32.012). Grouped
  Q/T (`0.013100/0.000206`) sum the envelope terms of all three
  windows; grouped tol (`96.130 = 32.116+32.002+32.012`) sums the
  per-window *bounds*. Both sums are exact retentions of applied
  quantities; neither is a re-derivation of the other.
- Group g3 (`w7..8`) is a single envelope window: grouped and window
  rows coincide (e.g. F-24 ch1: grouped `3/2 tol=32.004` = w7
  `3/2 tol=32.004`), so no decomposition question arises.
- The differing window in every grouped finding band is
  envelope-backed (`s_b` finite, `supported=true`); no finding
  depends on a TNS-reused window's tolerance. This is asserted per
  window in the retained tests, not inferred from the grouped row.
