## A. Verdict

**PASS WITH FINDINGS.**

The central numerical claim is independently supported: every one of the 28
R2.1-B probe findings F-03…F-30 maps to a supported envelope comparison whose
stored-energy delta is at or below the approved band-specific tolerance
(`max(32, Q_b + T_b + 1.5) + E_ref/500`), with zero failures and zero
unsupported comparisons. I reproduced the retained 56-row `G1-BAND` evidence,
the F-24, Class B and scale-edge deep dives, the maximum-utilisation rows, and
the R1 regression results independently. The FPE/Q31 stored-energy operands
also reproduce the exact `real_scale`/`is_scale` values of the R2.1-B owner
ledger for F-19…F-26, which independently connects the G-1 energy evidence to
the findings.

There are non-blocking evidence/documentation findings (detailed in §I):

- the report's claim that F-24 has the **largest finding-band utilisation** is
  false; the largest adjudicated finding row is **F-26** at
  1/32 = 0.031250 (F-24 is 0.031246, and 20 long rows are 0.031248);
- the report's "Max Class B: quiet f11 ch1 b7 … mapped sum 16122" quotes the
  wrong mapped sum for that case (the quiet b7 row has `Σ|X| = 37`; 16122 is
  the narrow probe band-10 case);
- the corner max utilisation 0.1182 is real but occurs on the first
  **zero-padded tail frame**, not on one of the 12 prescribed probe frames;
- grouped `BandRow` `Q_b/T_b/R` are not the "exact applied terms" for groups
  containing TNS-reused windows: the grouped tolerance is the sum of
  per-window bounds, and TNS windows contribute `q31_tol`, not the envelope
  terms. The tolerance/utilisation themselves are correct;
- the retained tests print the 56 finding rows but not the contributing
  per-window F-19/F-21 rows; I recovered those with an external diagnostic
  copy (they are envelope-backed and pass).

None of these changes a pass/fail row or the central conclusion, so the
verdict is PASS WITH FINDINGS rather than PASS or FAIL.

## D. Priority case analysis

### D.1 F-24 (narrow f1, group 3, local band 2, IS band 44)

Independently reproduced from the retained `G1-F24` output:

- Grouped ch1: `want=2`, `got=3`, `Δ=1`, `Q_b=0.000516`, `T_b=0.000002`,
  `R=1.5`, `tol=32.004`, `util=0.031246094`, `supported=true`,
  `failed=false`.
- Contributing window ch1 w7 b2: identical `Q_b/T_b/tol/util`,
  `s_b=22`, `s0=14`, `width=4`, `sum_abs_x=17305`.
- Group 3 has exactly one window (w7), so the grouped operands are that
  window's operands: ch0 `40/40`, ch1 `3/2`; no grouped saturation.
- No sentinel case at g3/b2: both stored values are nonzero, and
  `sum_abs_x=17305 > 0`, so neither Class A nor Class B applies.

**Derivation check.** With `final_shift f=3`, `s0=14`, `s_b = 2(14−3)=22`,
`n=4`, `Σ|X|=17305`:

```text
Q_b = 2^(2·3−31)·17305 + 4·2^(2·3−33)
    = 2^-25·17305 + 4·2^-27
    = 0.000515759 + 0.000000030 = 0.000515789
T_b = 2·4·2^-22 = 0.000001907
R   = 1.5
tol = max(32, 0.000515789 + 0.000001907 + 1.5) + 2/500
    = 32 + 0.004 = 32.004
util = 1 / 32.004 = 0.031246094
```

The envelope is supported: no mapping saturation, no accumulation/`<<1`
wrap, no negative re-shift overflow, `s_b=22 < 31` (no clamp), and no
non-finite term. The approved floor `max(32, …)` is the binding term; the
relative term `2/500 = 0.004` is not what covers the difference. This is the
formula of `05` §9.2 operating at a near-zero band, not a new tolerance.

**Ld consequence.** `calc_ld_data(2) = -1,006,629,047` and
`calc_ld_data(3) = -987,004,883`; the delta is exactly **19,624,164**.
`real_scale = e_ld_l − e_ld_r` with `e_l=40` therefore moves from
**145,016,039** (Q31) to **125,391,875** (FPE), `is_scale` 9→7, and
`2^(19,624,164·64/2^31) = 1.4991` (1.76 dB). The stored-energy delta is one
LSB (3 vs 2); the 19.6M figure is Ld-domain, not stored-energy. The large Ld
difference follows deterministically from the stored values.

**Verdict:** F-24 passes the approved envelope: supported, Δ=1 ≤ 32.004,
utilisation 3.1246%, no sentinel, no unsupported comparison. It is not the
largest finding-band utilisation (see N-1).

## E. Envelope integrity

### E.1 Implementation checked

`envelope.rs` implements the approved formula exactly:

```text
s0_b = max(0, maxScale_b − 4)
s_b  = min(2(s0_b − finalShift), 31)
Q_b  = 2^(2f−31)·Σ|X_j| + n_b·2^(2f−33)
T_b  = 2n_b·2^(−s_b)
tol_E(b) = max(32, Q_b + T_b + 1.5) + E_ref/500
```

Source-verified details:

- **Scale reconstruction:** `scale0 = (max_scale − 4).max(0)`; the audit
  reconstructs the pre-representation-shift mapping with
  `m = mdct_scale + final_shift` and `maxscale + final_shift`, matching the
  production representation shift (`psy.rs` shifts the Q31 spectrum and
  subtracts `f` from `maxscale`/`mdct_scale`). The Q31 identity gate
  independently reproduces the stored energy.
- **Shift arithmetic:** `s_b` is computed in i64 and clamped to 31 for
  display; `shift_clamped` is set only when `2(s0−f) > 31`, and a nontrivial
  clamped comparison is unsupported. The finding bands have `s_b` 18–24, no
  clamp.
- **Rounding/truncation:** `q31_stored_energy` mirrors `s = X << s0`,
  `(s·s)>>32`, wrapping accumulation, `e_raw = tmp << 1`, and the signed
  re-shift. The `fpe_stored_energy` identity is an independent round. The
  decomposition gate bounds mapping by `Q_b`, truncation by `T_b + 1`, and
  boundary by 0.5.
- **Accumulation/overflow:** the exact `supported_domain` detector rejects
  left-shift wrap, `Σ floor(s²/2^32) > i32::MAX>>1`, and negative re-shift
  overflow, including `maxScale < 4`; it is not a blind shortcut.
- **Mapping saturation:** `map_q31` clamps and flags out-of-range; a
  saturated comparison is unsupported, never passed.
- **Negative intermediates:** `scale_b < 0` preserves left-shift
  amplification; the re-shift guard checks representability.
- **Unsupported-domain:** saturation, accumulation/`<<1` wrap, negative
  re-shift overflow, shift clamp, and non-finite terms are surfaced through
  `unsupported_reason`; `record_energy` puts them in `unsupported` and does
  not count them as passing; `assert_clean` fails on any.
- **Sentinel classes:** Class A (`phys>0`, all mapped lines zero, Q31 stored
  zero) and Class B (`sum_abs_x>0`, Q31 stored zero, FPE stored positive) are
  classified by actual stored/mapped state, not by Ld crossing.
- **Long/short/grouped:** long rescale, short per-window, grouped sums,
  spread propagation, thresholds, and Ld are handled by the existing audit.
  Grouped saturation (`i32::MAX`) is unsupported. TNS-reused windows retain
  `q31_tol`; F-6 short-TNS with `tnsSpecShift != 0` is instrumented and was
  not observed.
- **`assert_clean`:** requires zero energy/value/Ld/identity failures and
  zero unsupported entries; it does not inspect the retained `rows` for gate
  semantics. This is unchanged.
