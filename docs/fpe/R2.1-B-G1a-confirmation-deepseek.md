### C4 — Grouped/TNS envelope explanation — CONFIRMED

The implementation matches the reconciliation note's description:

- In `audit.rs::compare_channel`, each per-window bound is pushed into
  `window_bounds`; for a TNS window the bound is
  `q31_tol_f(want_e) = 32 + |want_e|/500`, while a non-TNS window uses the
  derived `env.tolerance(want_e)`. The TNS per-window energy row is marked
  `reused = true`, with `Q_b = T_b = 0`; no single-band envelope is attached
  to that stored-energy row (short TNS retains the envelope separately for
  the Ld comparison).
- `compare_grouped` computes `bound += window_bounds[w][b]` over the group's
  windows. Therefore the grouped tolerance is the sum of the **applied
  per-window bounds**, including retained `q31_tol` for TNS-reused windows.
- The same loop sums `env.q`, `env.t`, `env.r` into grouped `Q/T/R` whenever
  a window has a `BandEnvelope` (short TNS windows retain `Some(env)`).
  Therefore grouped Q/T/R are sums of computed envelope terms, not a
  re-derivation of the summed tolerance. The printed per-window row for a
  TNS window shows `Q_b = T_b = 0` because it is a reused-kernel record, so
  grouped Q/T/R cannot be reconstructed from the printed TNS rows; the
  report now says exactly this.

Example (F-19 ch0, g1/b9): grouped `tol = 96.130 =
32.116 [w1 envelope] + 32.002 [w2 TNS] + 32.012 [w3 TNS]`; grouped
`Q = 0.013100`, `T = 0.000206`, `R = 4.5`. The three-window group is
`w1..4` in half-open notation (w1, w2, w3), not four windows.

Affected rows are the grouped rows for F-19/F-20/F-21/F-22 (g1/g2 contain
TNS-reused w2/w3 and w5/w6). F-23…F-26 use g3, a single envelope-backed
window w7, so grouped Q/T/R/tol coincide with the window terms:

| Finding | Grouped Q / T / R | tol | Equivalent window |
|---|---:|---:|---|
| F-23 ch0 g3/b1 | 0.001081 / 0.000008 / 1.5 | 32.026 | w7 b1 |
| F-24 ch1 g3/b2 | 0.000516 / 0.000002 / 1.5 | 32.004 | w7 b2 |
| F-25 ch0 g3/b9 | 0.004368 / 0.000092 / 1.5 | 32.116 | w7 b9 |
| F-26 ch1 g3/b10 | 0.000481 / 0.000001 / 1.5 | 32.000 | w7 b10 |

No calculation or acceptance rule was changed. The report §8 explains the

## 5. Numerical and implementation invariants

### 5.1 R1 envelope formula and implementation — unchanged

`tests/envelope.rs` still implements the approved `05` §9.2 formula:

```
Q_b = 2^(2·finalShift−31) · Σ|X_j| + n_b · 2^(2·finalShift−33)
T_b = 2·n_b · 2^(−s_b)
R   = 1.5
tol_E(b) = max(32, Q_b + T_b + 1.5) + E_ref/500
```

`band_envelope` computes `scale0 = max(0, maxScale−4)`,
`scale_b = min(2(scale0−final_shift), 31)`, `q`, `t`, `r = 1.5`,
`base = max(32, q+t+r)`, and `tolerance(e_ref) = base + |e_ref|/500`.
`Q_b` carries the half-LSB mapping contribution and the `n_b`
second-order term; `T_b` carries the per-square truncation/re-shift floor;
`R = 1.5` covers the re-shift floor and the FPE round-to-nearest boundary.
`unsupported_reason` still rejects mapping saturation, accumulation/`<<1`
wrap, negative re-shift overflow, non-finite terms, and a non-trivial
comparison with the re-shift exponent clamped to 31. The exact
`supported_domain` detector checks every left shift for i32
representability, bounds the non-negative accumulation by
`i32::MAX >> 1`, and uses an i128 comparison for the negative re-shift;
`MAX_FINITE_ENERGY_TOL` still caps supported tolerances. The file mtime
(2026-11-17 16:37) predates G-1 and G-1a; no G-1a edit is present.
