## 2. Production margin semantics (inputs and transcription)

### 2.1 Operands

Per stereo band, each engine arm supplies six Q31 log-domain integer
operands (all `i32`):

| Operand | Meaning |
|---|---|
| `eld_l`, `eld_r` | left/right channel energy Ld |
| `tld_l`, `tld_r` | left/right threshold Ld |
| `em`, `es` | mid/side energy Ld |

Cross-arm deltas are absolute: `dEL = |eld_l_q − eld_l_f|`, likewise `dER`,
`dEm`, `dEs`, `dTL`, `dTR`. This operand-domain reading (all deltas are Q31
log-domain absolute deltas) is the one documented at the definition site
(`fn b_closed` doc comment and `fn validate_ms_band` delta computation in
`rust/src/aac_enc/fpe/tests/is_ms.rs`).

### 2.2 First-pass MS margin (exact transcription)

The production first pass (`ms_stereo.cpp:185-201`, upstream FDK reference)
is transcribed in halved-shift `i64` form by `ms_first_pass_margins`
(`fn ms_first_pass_margins` in `rust/src/aac_enc/fpe/tests/is_ms.rs`):

```text
min_tld = min(tld_l, tld_r)
pnlr    = (tld_l>>1) − (max(eld_l,tld_l)>>1)
        + (tld_r>>1) − (max(eld_r,tld_r)>>1)
pnms    = min_tld − (max(em,min_tld)>>1) − (max(es,min_tld)>>1)
M       = pnms − pnlr − 1
use_ms  ⟺  M ≥ 0        (production strict `pnms > pnlr`)
```

`>>1` is the arithmetic shift (floor division by 2, including negatives).
The transcription is not trusted: replay-equality gates 1–2 assert it
against the production `ms_stereo_mirror` output on every frame of the
381-frame corpus (re-run green, P0-A §6.1). The margin functions are
annotation-only; nothing in production calls them.

### 2.3 Supported domain (unchanged)

`ms_band_supported` (`fn ms_band_supported` in
`rust/src/aac_enc/fpe/tests/is_ms.rs`) excludes a band from bound
validation when either arm carries the zero-energy sentinel `i32::MIN` in
any of the four energy-Ld operands (`eld_l`, `eld_r`, `em`, `es`), or when
the band is IS-coded on either arm (IS bands skip the MS first pass by C
design). Unsupported bands are recorded (`DomainUnsupported`), never counted
as validated. The derivation below holds for arbitrary **finite** integer
operands; the domain rule is retained unchanged because a sentinel is not a
physical log value (§4.3).

## 3. Derivation of the closed-form bound

### 3.1 Lemmas

**L1 — Shift lemma.** For all integers `a, b`:
`|(a>>1) − (b>>1)| ≤ ceil(|a−b|/2)`.

*Proof (parity accounting).* Assume `a ≥ b`, write `a = b + d`, `d ≥ 0`.
`floor((b+d)/2) − floor(b/2)` equals `floor(d/2)` when `b` is even and
`floor(d/2)` or `ceil(d/2)` when `b` is odd (the carry from `b`'s low bit
adds at most 1); in all cases it lies in `{floor(d/2), ceil(d/2)}` and is
non-negative, hence `≤ ceil(d/2)`. The case `a < b` is symmetric. ∎
Verified exhaustively on `[−2000, 2000]²` (16,008,001 pairs) plus 2,000,000
random full-width `i32` pairs: 0 failures (§5.1).

**L2 — min/max Lipschitz.** For all integers:
`|max(a1,b1) − max(a2,b2)| ≤ max(|a1−a2|, |b1−b2|)`, and likewise `min`.

*Proof.* `max(a1,b1) ≤ max(a2 + |a1−a2|, b2 + |b1−b2|) ≤ max(a2,b2) +
max(|a1−a2|, |b1−b2|)`; swap roles for the symmetric inequality. `min`
follows by `min(x,y) = −max(−x,−y)`. ∎

**L3 — Ceil grouping (parity accounting).** For non-negative integers
`a, b, c, d` with `S = a+b+c+d`:
`ceil(a/2) + ceil(b/2) + ceil(c/2) + ceil(d/2) ≤ ceil(S/2) + 2`.

*Proof.* `ceil(x/2) = (x + (x mod 2))/2`, so the left side is
`(S + k_odd)/2` where `k_odd ∈ {0,…,4}` counts odd terms; the right side is
`(S + (S mod 2))/2 + 2`. Since `k_odd ≡ S (mod 2)` and `k_odd ≤ 4`, the
difference `(k_odd − (S mod 2))/2 ≤ 2`. ∎

Also used: `ceil(x/2) ≤ x` for integers `x ≥ 0`, and
`2·ceil(T/2) = T + (T mod 2) ≤ T + 1`.

### 3.2 Derivation steps

Let `x` (Q31 arm) and `y` (FPE arm) be two supported-domain operand sets;
`Δ` denotes `value(x) − value(y)`. The `−1` in `M` cancels:
`ΔM = Δpnms − Δpnlr`.

**Step 1 — rewrite each `pnlr` pair.** Define
`g(eld,tld) := (tld>>1) − (max(eld,tld)>>1)`. Case split:

- `eld ≥ tld`: `max = eld`, so `g = (tld>>1) − (eld>>1) ≤ 0` (shift is
  monotone), and `min(0, (tld>>1)−(eld>>1))` equals the same value.
- `eld < tld`: `max = tld`, so `g = 0`, and `(tld>>1) − (eld>>1) ≥ 0`, so
  `min(0, ·) = 0`.

Hence `g(eld,tld) = min(0, (tld>>1) − (eld>>1))` identically. Since
`min(0,·)` is 1-Lipschitz, L1 gives
`|Δg| ≤ ceil(dEL/2) + ceil(dTL/2)`. With
`pnlr = g(eld_l,tld_l) + g(eld_r,tld_r)`:

```text
|Δpnlr| ≤ ceil(dEL/2) + ceil(dER/2) + ceil(dTL/2) + ceil(dTR/2).
```

**Step 2 — rewrite `pnms`.** Write `min_tld = 2·(min_tld>>1) + r` with
`r ∈ {0,1}` (low bit / parity). The identity

```text
(max(em,min_tld)>>1) − (min_tld>>1) = max(0, (em>>1) − (min_tld>>1))
```

holds by the same case split (`em ≥ min_tld`: both sides
`(em>>1)−(min_tld>>1) ≥ 0`; `em < min_tld`: both sides 0). Therefore

```text
pnms = r − max(0, (em>>1)−(min_tld>>1)) − max(0, (es>>1)−(min_tld>>1)).
```

With `T := |Δmin_tld| ≤ max(dTL,dTR)` (L2), `|Δr| ≤ 1`, and 1-Lipschitzness
of `max(0,·)` plus L1:

```text
|Δpnms| ≤ 1 + ceil(dEm/2) + ceil(dEs/2) + 2·ceil(T/2).
```

**Step 3 — assemble.** With `S := dEL + dER + dEm + dEs`, triangle
inequality, L3, `ceil(x/2) ≤ x`, and `2·ceil(T/2) ≤ T + 1`:

```text
|ΔM| ≤ 1 + [ceil(dEL/2)+ceil(dER/2)+ceil(dEm/2)+ceil(dEs/2)]
         + [ceil(dTL/2)+ceil(dTR/2)] + 2·ceil(T/2)
     ≤ 1 + [ceil(S/2) + 2] + (dTL + dTR) + (T + 1)
     = ceil(S/2) + dTL + dTR + T + 4.
```

**Step 4 — close the constant.** If `T = 0`:
`|ΔM| ≤ ceil(S/2) + dTL + dTR + 3`. If `T ≥ 1`: `T + 4 ≤ 2T + 3`, and
`T ≤ max(dTL,dTR)`. In both cases:

```text
|M_q − M_f| ≤ ceil((dEL+dER+dEm+dEs)/2) + dTL + dTR + 2·max(dTL,dTR) + 3
            = B_closed.   ∎
```

The `+3` constant is exactly accounted for: **1** from the `min_tld` parity
term `r`, **2** from the four-way ceil grouping (L3); the `T = 0` case shows
the constant is exactly sufficient. (The implementation's `b_closed` doc
comment, corrected under P0-C N6, now records this exact accounting — **1**
(`min_tld` parity) + **2** (four-way ceil grouping) — and notes the `−1` in
`M` cancels in the delta; the pre-N6 "strict-`>` unit plus halving floors"
wording is superseded. No numerical consequence.)

### 3.3 Robustness corollary

If `|M_q| > B_closed` then `use_f = use_q`: `M_q ≥ B+1` forces
`M_f ≥ M_q − B ≥ 1` (use 1); `M_q ≤ −B−1` forces `M_f ≤ M_q + B ≤ −1`
(use 0). Hence every in-domain decision flip is a close call within `B` of
the boundary. This is the retained debug assertion in `fn validate_ms_band`
(`rust/src/aac_enc/fpe/tests/is_ms.rs`).

### 3.4 Assumptions register

1. **Exact margin transcription** (§2.2) — gated by per-frame replay
   equality against production (re-run green, §5.3).
2. **Finite operands** — the supported-domain rule (§2.3). The derivation
   itself holds for arbitrary finite `i32` operands; it does not need the
   threshold floor (`−33/64` Ld floor) or non-positive-energy constraints.
3. **Pure integer arithmetic** — no floating point enters the bound.
4. **Delta reading** — absolute Q31 log-domain deltas (§2.1), as documented
   at the definition site.

## 4. Comparison with the previously implemented formula

### 4.1 Identity

The reconstructed bound is **identical** to the formula already implemented
and used in every acceptance calculation:

- Retained implementation, `fn b_closed` in `rust/src/aac_enc/fpe/tests/is_ms.rs`:

  ```rust
  fn b_closed(d_el: i64, d_er: i64, d_em: i64, d_es: i64, d_tl: i64, d_tr: i64) -> i64 {
      let half_sum = d_el + d_er + d_em + d_es;
      debug_assert!(half_sum >= 0, "B_closed deltas are absolute values");
      let half_ceil = (half_sum + 1) / 2;
      half_ceil + d_tl + d_tr + 2 * d_tl.max(d_tr) + 3
  }
  ```

- Recovered original verification scaffold (`r21b_verify/ms_bound_verify.rs`,
  P0-A R2): `B = ceil((dEl+dEr+dEm+dEs)/2) + dTl + dTr + 2*max(dTl,dTr) + 3`.
- Owner-review instances: F-01 `B = ceil(256038/2)+3 = 128022` (shift
  128020, slack 2); F-19 `B = ceil(738513/2)+3 = 369260` (shift 369256,
  slack 4) — both reproduced exactly (§5.2).

**No difference; no implication for decision behaviour.** The reconstruction
supplies the missing proof, not a new bound.

### 4.2 Empirical tightness observation (no action)

Over 28,409,561 checked operand pairs (§5.1) the minimum slack `B − |ΔM|`
was **1**; no pair attained `B` exactly. The bound may be loose by 1 in some
regimes. **No tightening is proposed or performed** — Phase 0 excludes
`B_closed` decision-behaviour changes.

### 4.3 Sentinel domain (unchanged)

The derivation treats operands as integers, so the F-01 instance
(both-arm `es_ld = MIN`, identical `min_tld`) satisfies the bound
arithmetically — the MIN terms cancel identically. The supported-domain rule
nevertheless excludes it, correctly: a sentinel is not a log value; a
one-sided MIN or a differing `min_tld` can flip the `max()` branch and make
the formula vacuous (~2^30 bound), not a meaningful close-call certificate
(DeepSeek numerical review §5.3). **The domain is not extended.** F-01/F-02
remain `DomainUnsupported`/reported, never bound-validated.
