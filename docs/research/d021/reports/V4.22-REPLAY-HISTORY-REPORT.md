### Per-case block-type sequences (real C, 0-based frames)

**Case 1: onset-stereo (frames 0-48)**
- Frames 0-2: LONG (0), LONG (0), LONG (0) → then START (1), SHORT (2), STOP (3) at frames 0-2? No.
- Actually: frame 0=SEQ1(START), frame 1=SEQ2(SHORT), frame 2=SEQ3(STOP), frame 3+=SEQ0(LONG)
- Short sequence: frames 0-2 (START, SHORT, STOP), then LONG from frame 3.
- Second short sequence: frames 24-25 (START, SHORT) — wait, let me check.

Actually, the real C capture shows:
- Frame 0: SEQ 1 (START)
- Frame 1: SEQ 2 (SHORT)
- Frame 2: SEQ 3 (STOP)

- Frame 25: SEQ 2 (SHORT)

The oracle originally used SHORT (SEQ 2) for frame 23 (0-based), which is wrong — real C uses LONG (SEQ 0).

## 3. Replay method and modifications

### Oracle modification

Added `D021_OVERRIDE_FILE` support to the oracle scratch copy (`enc_oracle.cpp`). When set, the oracle reads a per-frame override file (format: `frame seq shape last_shape`, 0-based) and overrides `lastWindowSequence`, `windowShape`, and `lastWindowShape` for every frame listed.

This is in addition to the existing `D021_OVERRIDE_FRAME`/`D021_OVERRIDE_SEQ`/`D021_OVERRIDE_SHAPE` single-frame override (which was used in V4.17).

### Override files

Created 4 override files with real C's block types for all frames:
- `/tmp/onset_all_blocktypes.txt` (49 frames)
- `/tmp/onset441_all_blocktypes.txt` (45 frames)
- `/tmp/sine_all_blocktypes.txt` (49 frames)
- `/tmp/multitone_all_blocktypes.txt` (49 frames)

### Replay method

For each case:
1. Set `D021_OVERRIDE_FILE` to the override file.
2. Set `D021_RING_FRAME` to the target frame (1-based).
3. Run the oracle.
4. The oracle overrides block types for every frame using real C's values.
5. Capture ring buffer for the target frame.

### Modifications made

- Oracle: `enc_oracle.cpp` — added `D021_OVERRIDE_FILE` support (reads per-frame overrides).
- No changes to real C capture or production code.
- All changes confined to oracle scratch copy.

## 6. Clear distinction between demonstrated facts and hypotheses

### Demonstrated (V4.22)

1. **Replaying with correct preceding-frame block types aligns ALL block-switching state.** The ring buffer, energy history, attack state, IIR states, accWindowNrg, maxWindowNrg, lastWindowSequence, and lastWindowShape all match between real C and corrected oracle.

2. **The original oracle's preceding frames used different block types.** The oracle's replay produced SHORT (SEQ 2) for frames where real C used LONG/START (SEQ 0/1). This is the D-021 blip.

3. **The block-type difference in preceding frames cascaded to the target frame.** The oracle's previous frames produced different `lastWindowSequence`/`lastWindowShape`, which changed the target frame's block-switching decision.

4. **With corrected history, the target frame's block type matches real C's.** The oracle's target frame now uses the same block type (SEQ 1 for START, SEQ 0 for LONG) as real C.

### Hypothesized (not yet demonstrated)

1. **The corrected oracle's MDCT matches real C's for SHORT frames.** Not tested — the target frames are START (0 non-zero MDCT). A SHORT-frame comparison would be needed.

2. **The Rust encoder matches real C when using the correct block type.** Not tested — Rust uses committed oracle vectors (which have the wrong block type). Re-running Rust with correct block types would be needed.

3. **The block-type difference is the sole cause of all D-021 blips.** Strongly supported by the evidence (all state matches with corrected history), but not definitively proven for all 10 blip frames (only 4 were tested).

## 7. Missing evidence and limitations

1. **SHORT-frame MDCT comparison:** The target frames are all START (0 non-zero MDCT). The SHORT-frame MDCT difference (640 vs 569 for onset-stereo frame 24) was not re-tested with corrected history. The ring buffer for frame 24 (SHORT) was not compared.

2. **Rust encoder not tested:** Rust uses committed oracle vectors (wrong block type). Re-running Rust with correct block types would be needed to verify Rust matches real C.

3. **Only 4 of 10 blip frames tested:** The experiment covered 4 of the 10 D-021 blip frames. The remaining 6 (stepdown f1, click f1, sweep f1, tonal-noise f1, sine-441k f1, stress f1) were not tested.

4. **Oracle override for preceding frames:** The override was applied to all frames in the override file (49-45 frames). Frames beyond the file's range use the oracle's computed block types. For the target frames (within range), this is sufficient.
