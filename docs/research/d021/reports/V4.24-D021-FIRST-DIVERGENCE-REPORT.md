## 3. Step 1 — Audit of the V4.23 comparison

### 3.1 What “S6 bits” means

- Oracle `S6FINAL total` (in `tools/enc-oracle/enc_oracle.cpp:2484-2490`) is `staticBits + usedDynBits + totFillBits + alignBits + elementExtBits(0) + globalExtBits(3)`. It is the raw-data-block payload without the 56-bit ADTS header. `s6qc.globHdrBits` is hardcoded to 56 (transport-probed constant via `tools/enc-oracle/tp_probe.cpp`; `adtsWrite_GetHeaderBits` with protection_absent=1, PCE absent).
- Real C value in V4.23 Table 7 is the ADTS frame length in bits (13-bit `aac_frame_length` field × 8), which includes the 7-byte (56-bit) header.
- The documented convention (`tools/enc-oracle/extract_s6.py:21-24`, `tools/enc-oracle/README.md:421-425`) is `S6FINAL total + 56 == real ADTS bits` wherever oracle inputs match the encoder. This holds for LONG frames (e.g., onset f23: oracle 64 + 56 = 120 = real 120, verified). V4.23’s `total+56` column therefore compares equivalent scopes (same fixture, same zero-based frame, stereo CPE, payload+header vs ADTS total). The quantities are equivalent; the scope is the same frame/channel.
