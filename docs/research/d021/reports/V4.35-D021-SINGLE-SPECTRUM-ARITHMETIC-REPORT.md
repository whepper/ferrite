## 3. C fixed-point recomputation (step 3: achieved by execution, not replica)

A faithful Python replica of C's data-dependent FFT block-scaling was not attempted; instead the ACTUAL C implementation (`mdct_block` + `dct_IV` + `fft`, pristine sources) was executed in an isolated scratch harness (`harness.cpp` alongside this report; steady-SHORT state, committed ring input; repo headers used read-only):
- Harness output reproduces the committed MDCT reference **0/1024, exponents all 9** — proving harness == production C pipeline and establishing the fixtures' provenance as genuine `mdct_block` output (not assumed).
- Deterministic across runs (SHA `6a9c163d…` twice).
- Scratch-only fold/pre-twiddle/FFT dumps (patched COPIES in /tmp, never the repo) give intermediate stages: fold at exp 2, post-pre-twiddle exp 2, post-FFT exp 7.

| boundary | C-side error vs exact | live-side error vs exact |

| fold (windowed sums) | ≤1.7e-5 (fMultDiv2 truncation chain) | incl. below |

One analysis pitfall caught and corrected during the work: comparing against tracked exponents initially suggested a scale mismatch; the uniform-1.0 ratio histogram across all bins at every stage proves the tracked exponents are the true scales (the /2 /4 factors are absorbed in FDK's exponent bookkeeping) and the transcriptions exact. A decimal-parse artifact (up to ~8 LSB, V4.32 method) was avoided throughout via bit-exact captures.

## 5. Limitations

- Within-FFT apportion (per-butterfly rounding vs block-shift losses vs twiddle quantization) not split; the FFT stage is implicated as a whole by elimination + magnitude.
- Post-twiddle's own rounding bounded only by remainder (~1e-5 scale); its ×4 gain of the FFT term is measured, op-level path not traced.
- Single frame/window-family evidence (onset f24 SHORT); LONG blocks not examined.
- No defect alleged against either implementation: both differ from exact math at their own precision levels (live ~100× closer to exact than C here); the gap is the expected consequence of fixed-point vs float pipelines, not a bug in either.
